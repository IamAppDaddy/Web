Let Us Fly: The Game - Documentation

This documentation outlines the "Let Us Fly" game, its controls, and how to use this template for a mobile app or game website, optimized for mobile viewing.

1. How the Game Works

"Let Us Fly" is an endless 3D flight game built with HTML5, JavaScript, and Three.js. You control an army propeller plane over a sea, dodging green tetrahedral obstacles (stones) and collecting yellow coins to maintain energy.

Key Gameplay Elements:

  • Objective: Fly as far as possible, avoiding obstacles and collecting coins. Game ends when energy depletes or the plane crashes.
  • Progression:
    • Distance: Increases as you fly.
    • Levels: Advance every 1000 units, increasing speed and enemy spawns.
    • Energy: Starts at 100, decreases with speed, replenished by coins (+3), reduced by enemies (-10).
  • Game Elements:
    • Plane: Army-style propeller plane, auto-moves forward; control height and lateral position.
    • Sea: Wavy ocean, rotates for forward motion effect.
    • Sky: Moving clouds for ambiance.
    • Coins: Yellow tetrahedrons, spawn in clusters, add energy.
    • Obstacles: Green tetrahedrons, spawn by level/distance, reduce energy on hit.
    • Particles: Visual effects for collisions/coin collection.
  • Audio:
    • Coin collection sound.
    • Enemy collision sound.
    • Plane engine sounds (start, loop, end).
  • Game States:
    • Playing: Active gameplay.
    • Game Over: Energy at 0, plane falls, score sent to Android app.
    • Waiting Replay: Tap to restart.
  • Performance: Uses requestAnimationFrame, supports touch/mouse, and resizes for mobile.

Controls:

  • Mobile/Touch:
    • Drag finger left/right to steer.
    • Drag up/down to adjust height.
    • Tap to replay after game over.

2. Using This Template

This self-contained HTML game uses Three.js, TweenMax, and assets (sounds, CSS). It's ideal for a website or mobile app via WebView.

Prerequisites:

  • Libraries: three.min.js, TweenMax.min.js.
  • Sound files: coin.wav, dash1.wav, dash2.wav, plane_start.mp3, plane_middle.mp3, plane_end.mp3.
  • CSS: demo.css, game.css.
  • Ensure correct file paths in HTML.

Creating a Game Website:

  1. Setup:
    • Place HTML (index.html), libraries, CSS, and sounds in folders (js/, css/, sounds/).
  2. Customize:
    • Edit game object for difficulty (speeds, spawns).
    • Change Colors or Three.js models (AirPlane, Ennemy).
    • Update HTML UI (score display).
  3. Host:
    • Use a server (e.g., Netlify, Python http.server).
    • Access via http://localhost/index.html.
    • Minify JS/CSS for production.
  4. Test: Verify audio (needs user interaction) and responsiveness.

Integrating into an Android App with WebView:

The game supports Android with a JavaScript interface for scores.

  1. Android Project:
    • Create project in Android Studio.
    • Add WebView in activity_main.xml: 
      <WebView
    android:id="@+id/webView"
    android:layout_width="match_parent"
    android:layout_height="match_parent"/>
  2. Load Game:
    • In MainActivity.java: 
      WebView webView = findViewById(R.id.webView);
webView.getSettings().setJavaScriptEnabled(true);
webView.getSettings().setDomStorageEnabled(true);
webView.getSettings().setMediaPlaybackRequiresUserGesture(false);
webView.loadUrl("file:///android_asset/index.html");
    • Copy HTML, JS, CSS, sounds to assets/.
  3. JavaScript Interface:
    • Add score interface: 
      webView.addJavascriptInterface(new WebAppInterface(this), "Android");

public class WebAppInterface {
    Context mContext;
    WebAppInterface(Context c) { mContext = c; }
    @JavascriptInterface
    public void receiveScore(int score) {
        Toast.makeText(mContext, "Score: " + score, Toast.LENGTH_SHORT).show();
    }
}
    • Game calls Android.receiveScore on game over.
  4. Permissions:
    • Add <uses-permission android:name="android.permission.INTERNET"/> in AndroidManifest.xml for URLs.
    • Enable android:hardwareAccelerated="true" for 3D.
    • Consider locking to landscape.
  5. Customize:
    • Extend JS interface (e.g., for pause, ads).
    • Add native UI (buttons, leaderboards).
    • Test touch and audio on devices.
  6. Publish: Build APK, optimize assets, submit to Google Play.

For iOS, use WKWebView. Debug audio/performance issues via console logs or WebView debugging.

Extend with leaderboards, power-ups, or multiplayer by modifying JS.
